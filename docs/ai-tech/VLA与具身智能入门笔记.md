# VLA 与具身智能入门笔记：从 0 到 1 看懂"会干活的机器人"

> 本笔记面向零基础读者，归纳 VLA（Vision-Language-Action）与具身智能的核心知识点，以 Physical Intelligence 公司的 π 系列模型（π0 → π0.5 → π0.6 → π0.7）为主线，覆盖基本概念、硬件常识、数据、架构、训练方法与代表成果。

---

## 一、什么是 VLA 与具身智能

**具身智能（Embodied AI）**：让 AI 从"屏幕里"走到"身边"——不再是只会聊天、画图的软件，而是拥有身体（机械臂、移动底盘等），能感知真实世界并实际动手干活的智能。

**VLA（Vision-Language-Action）模型**：目前具身智能最重要的一条技术路线。三个字母对应它的三种输入：

| 输入 | 含义 | 例子 |
|---|---|---|
| **V**ision（视觉） | 相机拍到的画面，通常 2~3 个相机（腕部相机看手里抓的东西，外部固定相机看全景） | RGB 图像 |
| **L**anguage（语言） | 人给机器人的指令 | "把这件衬衫叠起来" |
| **A**ction（动作） | 机器人各个关节当前的状态（本体状态） | 关节角度、夹爪开合度 |

**输出**：一串数字，代表机器人每个关节接下来应运动到的角度。执行完一个动作，相机再拍一帧，循环往复，机器人就"动"了起来。

**一个关键理解**：机器人的"动作"不是一句话，而是纯数字。模型每个时间步都重复"看图 + 读指令 + 感知关节 → 输出下一组关节角度"的过程，就像人走路时每一步都在实时调整肌肉一样。

## 二、机械臂硬件常识（零基础必看）

以经典的 UR5e 单臂机械臂为例：

- **自由度（DOF）**：能独立转动的关节数量。UR5e 有 6 个自由度，大致对应末端在空间中的位置（XYZ）和姿态（三个旋转角，即 roll/pitch/yaw）。
- **关节 = 电机 + 编码器**：电机负责转，编码器负责读出当前角度并传给大模型。
- **夹爪（gripper）**：机器人的"手"，开合程度可用 0~1 之间的数字表示。
- **腕部相机**：装在手腕上，跟手一起动，专门看手里抓了什么；旁边还有固定机位相机看全景。
- **底座与控制器**：负责整体支撑与底层运动控制。
- **频率（赫兹 Hz）**：机械臂每秒执行几条动作。50Hz = 每 20 毫秒做一个动作。频率太低，动作一顿一顿，像叠衣服这种精密连续操作根本做不了——所以控制频率是能否干精细活的关键。
- **双臂平台的本体状态**：通常是一个 18 维向量（左臂 6 维 + 右臂 6 维 + 两个夹爪各 1 维 + 底盘、升降躯干等），单臂不足 18 位则补 0。
- **关节控制 vs 末端控制**（两种"动作表示方式"）：
  - **关节控制**：直接输出每个关节转多少度（如 6 个关节角 + 夹爪 = 7 个数）。数字和这台机械臂的构造"绑死"，换一台机械臂同样数字含义就不同。π0~π0.6 用这种。
  - **末端控制**：只输出夹爪要到达的空间位置（XYZ）和朝向（roll/pitch/yaw）+ 夹爪。它需要 **逆运动学求解器（IK）** 作为"翻译器"，把末端坐标反推成各关节角度再交给电机。RT-2、OpenVLA 及许多开源数据集用这种。
  - 两种表示混在一起训练时，同一画面会对应两套完全不同的目标值，模型会"学成平均值"——所以 π0.7 在输入里显式标注每条数据用的是哪种控制模式。

## 三、训练数据长什么样

一条完整的演示叫做一个 **episode**（比如叠一件衣服的 30 秒全过程）：

- 50Hz 机械臂 × 30 秒 = 1500 帧；
- 每帧包含：3 张相机图像 + 文本指令（如"叠衣服"）+ 本体状态向量 + 每帧对应的下一拍动作（action）；
- 训练时常取一个样本，用它后面 50 步动作作为监督信号；
- 相比大语言模型，VLA 的文本**非常稀疏**：30 秒动作往往只对应一句指令。

**数据从哪来**：
1. **遥操数据（teleoperation）**：人拿遥控器带着机器人把任务做一遍，系统录下画面、关节角和人类指令。这是最主要的数据来源。
2. **自主数据**：模型自己上真机跑任务留下的数据（含成功、失败、人类中途接管），π0.6 之后大量引入。
3. **网页/人类视频数据**：图片描述、视觉问答、物体检测、人类第一视角视频等，不含机器人动作，主要用于提升泛化能力。

## 四、VLA 发展脉络（前 π0 时代）

### 1. RT-2（Google DeepMind，2023）——"VLA 之父"

- 第一次把**大语言模型直接输出机器人动作**：把连续动作离散化——动作拆成 8 个整数（1 个结束符、3 个末端位置增量、3 个旋转增量、1 个夹爪），每一维切成 256 个"桶"，动作像文字 token 一样输出。
- 用现成的视觉语言模型（PaLM-E，55B）像回答问题一样"写出"这 8 个数，网页图文问答数据与机器人数据混训，不增加参数。
- 意义：借到了大模型的语义泛化能力，并首次提出 VLA 这个词。
- 致命缺陷：**太慢**——1~3Hz，远低于 50Hz 机械臂的要求；且 Google 全套闭源，无法复现。
- 花絮：RT-2 团队里的四位核心作者后来离开 Google，于 2024 年 3 月在旧金山创办了 **Physical Intelligence**（种子轮 7000 万美元，A 轮 4 亿/估值 24 亿，B 轮 6 亿/估值 56 亿），也就是 π 系列的公司。

### 2. OpenVLA（Stanford 牵头，2024.6）——开源的里程碑

- 范式与 RT-2 相同（动作离散成 token），但**完全开源**：视觉编码器用 SigLIP + DINOv2 拼接，语言模型用 Llama-2 7B，输出 7 个动作 token（每位 256 桶），训练用交叉熵损失。
- 97 万条轨迹，64 张 A100 训 14 天，Bridge 平台成功率 70.6%，超过闭源的 RT-2。
- 提供了微调方法，高校实验室一张卡就能微调。它是几乎所有后续 VLA 工作对比的 baseline。

### 3. 第一代范式的四大问题

1. **推理慢**：语言模型架构一个 token 一个 token 地"嘣"动作，控制频率最高 6Hz；
2. **离散化损失精度**：动作本是连续的，强行切成 256 个桶精度受损；
3. **单图输入**：没有本体状态、没有历史记忆；
4. **数据规模不够、训练配方不成熟**。

## 五、π0（2024.10，开源）：奠定 VLA 现代范式

π0 针对上述问题开出三剂药方——**数据、架构、训练配方**。

### 1. 数据：量级碾压

- 约 90 万+ episode、一万多小时，含 7 种机器人构型、68 类任务（不是"不同杯子算不同类"，而是 68 类真实世界的重要任务类别）。
- 对每类数据**加权**，保证各类数据量均衡。

### 2. 架构：VLM 骨干 + Action Expert（π 系列的标志性设计）

- 骨干：Google 开源的 3B 视觉语言模型 PaliGemma（图像编码器 SigLIP），3 张图 + 文本指令一起编码。
- **关键创新：外挂一个 300M 参数的 Action Expert（动作专家）**，本质是一个以 **flow matching** 为基础的"扩散头"，**一口气生成整段 50 步动作块**，而不是逐 token 输出。

**为什么必须用扩散/flow matching，而不能直接回归（L2 loss）？** 因为机器人动作分布是**多峰**的：比如"绕过碗拿盘子"，从上面绕、下面绕都是正确解，人类演示里两种都有。L2 回归会学出两种走法的"平均"——一条直接撞碗的直线，必然失败。flow matching 能表示 50 步动作的**联合分布**：采样时要么整条走上面、要么整条走下面。

**注意力掩码设计**：输入分三块（图文块 → 本体状态块 → 带噪动作块）。图文块看不到后面的动作/状态（保护 VLM 预训练知识不被奇奇怪怪的动作 token 破坏）；状态和动作块可以看到前面的图文。块间只能"往前看"。

**KV cache 复用**：图文状态那 800 多个前缀 token 在扩散的每一步去噪中都不变，且 mask 保证它们不受动作 token 影响，所以只算一次 K/V，重复利用——这是速度能上去的关键工程细节。实际推理时预测 50 步只执行前 25 步（留缓冲）。

### 3. 训练配方：预训练 + 后训练两段式

- **预训练**：全部数据（包括脏数据）喂进去，目标是覆盖尽量多的任务/场景/机器人。
- **后训练**：筛选每类任务的高质量数据微调（每类几小时到一百多小时），让动作更流畅一致。
- 为什么分两段？只用高质量数据，模型学不会"犯错之后如何恢复"；预训练里的错误数据教会它纠错——这是 π 系列错误恢复能力的来源。

**成果**：发布时性能遥遥领先 OpenVLA、RT-2，无论是语言跟随还是微调任务。

## 六、π0.5（2025.4，开源）：走进没见过的真实家庭

π0 的问题：训练和评测都在相同环境，没验证泛化性；动作都是"拿杯子"这类**原子动作**，任务时长短。π0.5 的目标：一句"把房间打扫干净"，机器人进一个**训练时完全没见过的家**，自主干 10~15 分钟的复杂家务——它是**第一个能实际部署使用的 VLA 模型**。

### 1. 两篇铺垫工作

- **π0-Fast（2025.1）**：解决"动作怎么离散成 token 才训得动"。原方案 50Hz 下相邻 token 数值变化太小，大量 token 无信息，next-token prediction 学不到东西。Fast 的做法：把 50 步动作归一化 → **DCT 变换**（时域→频域）→ 量化取整（高频系数大多变 0，真正压缩发生在这里，且高频抖动多是机械噪声，丢弃有益）→ 展平 → **BPE 分词**（词表 1024）。全程可逆，只有 2 个超参数。效果：原本成功率≈0 的任务提升到 65~85%；训练 GPU 省五倍；代价是推理慢（自回归逐 token，比 flow 版慢约 7 倍）。
- **Hi Robot（2025.2，ICML 2025）**：解决"复杂指令怎么拆"。用两个 3B 模型：高层模型把"做个三明治不要番茄"拆成一串原子指令（"拿起一片生菜"…），低层 VLA 执行。缺陷：高层没记忆、高层低层分开训练（高层不知道低层能不能执行它输出的指令）。

### 2. 数据：从 1 类扩展到 5+ 类

| 类型 | 内容 |
|---|---|
| MM | 移动双臂机器人在约 100 个真实家庭做家务（400 小时，仅占 2.4%，但与测评直接对应） |
| ME | 固定机械臂在更多家庭采的数据（更好采集、场景更多，但任务较简单） |
| CE | 实验室跨本体数据（+ 开源 OXE 数据集） |
| HL | 高层标注：给多阶段任务标子任务文本 + 物体检测框（bounding box） |
| WD | 网页数据（caption、VQA、COCO 检测等），无机器人动作，提升泛化 |
| VI | 语言遥操数据（后训练新增）：人不碰手柄，盯着场景实时下达子任务，记录"总任务→子任务"配对；去掉它成功率 78%→60%，非常重要 |

五类数据能一起训的秘诀：**全部统一 token 化**（动作是 token、子任务是 token、检测框是 token、VQA 答案也是 token）。

### 3. 架构：骨干不变，进出变了

- 骨干（PaliGemma 3B + SigLIP + 300M action expert）与 π0 完全相同。
- **输入变化**：本体状态不再走 action expert，而是离散化成文本 token 与图像指令一起进 VLM。
- **输出变成三种**：① 文本（子任务/描述/检测框）② Fast 风格的离散动作 token ③ action expert 的连续动作（flow matching）。
- **注意力规则**：前缀 token（图/指令/状态）之间双向互相可见；fast token 只能看前缀、内部因果；action expert 可看前缀、内部互相看，但**看不到 fast token**——因为两者表征同一段动作，能看到就会"偷懒抄 fast"。

**高层低层合一**：与 Hi Robot 两个模型不同，π0.5 是**同一个模型的两种输出模式**（先自回归输出子任务，再用 action expert 出动作块），共享权重。实验：模型自己出子任务成功率 78% > 人类专家给子任务 63% > GPT-4 零样本 57%。

**推理流程**：① 高层自回归采样一条子任务（"clean the bedroom" → "pick up the pillow"）② 低层拿 3 路相机画面 + 这句**子任务**（不看总任务）生成 50 步动作块执行，循环。

### 4. 训练：两段式的新玩法

- **预训练（28 万步）**：α=0，flow 损失不参与，纯 token 训练（文本交叉熵 + fast 动作 token），相当于训一个"词表里多了动作 token"的普通 VLM——训练快、指令跟随好。
- **后训练（8 万步）**：随机初始化的 action expert 接上，α=10，两项损失一起训；数据换成 MM/ME 高质量细粒度数据 + VI 语言遥操数据，去掉实验室 CE 数据。
- 结果：真实家庭任务（如 dishes in sink）成功率 93%，而 π0 只有 18~42%。

## 七、强化学习基础（理解 π0.6 的必修课）

### 模仿学习（Imitation Learning / SFT）的两个天花板

π0~π0.5 都属于模仿学习：数据来自人遥操，目标就是"看到这个画面，模仿人当时做的动作"。隐藏假设是**数据里每个动作都是对的**。两个问题：

1. **复合误差（compounding error）**：模型自己跑时每步有一点点小偏差，误差不断累积，到某一步状态就跑出了训练数据覆盖的范围，模型只能瞎猜，越猜越偏，彻底失败。
2. **上限是人**：永远在模仿人类演示，最快也只能和操作员一样快。

### 强化学习核心概念（用外卖骑手理解）

| 概念 | 定义 | 外卖骑手版 |
|---|---|---|
| 策略 π | 输入观测 o，输出动作 a | 骑手本人 |
| 环境 | 世界，反馈新观测和奖励 | 送餐的城市 |
| 奖励 reward | 每一步的得分（数字） | 每多花一分钟扣一分；餐撒了/超时一次扣一大笔 |
| 回报 | 一条 episode 所有奖励之和 | 这一单的总分（负的） |
| 价值 V | 从当前状态按当前策略走下去预期能拿的回报 | 导航软件："从这里出发平均还要多久送到" |
| 优势 A | 实际回报 − 价值预期；正=比平均好，负=比平均差 | 出发时导航说 20 分钟，跑 5 分钟后导航说还剩 12 分钟 → 20−5−12=3 分钟，比预期快 3 分钟，优势 +3 |
| 总目标 | 找策略让期望回报最大 | 平均每单用时最短 |

**两种学法的对比**：跟着老骑手把路线走一遍 = 模仿学习（最快和老骑手一样快）；自己跑单、看用时、按优势改进跑法 = 强化学习（没人教正确路线，却能比老骑手更快）。

## 八、π0.6（2025.11，未开源）：强化学习 × VLA

π0.6 的成绩单：连续 13 小时不间断做浓缩咖啡；进没见过的家连续 2 小时无人干预叠没见过的衣服；进工厂组装真实包装纸箱；最难任务吞吐量比 π0.5（纯示范训练）翻倍以上，失败率减半。核心方法是 **RECAP**，一个三步循环：**采数据（真机跑 + 标成功/失败）→ 训练价值函数 → 用价值函数训策略**，逐子任务多轮迭代。

### 1. 奖励设计：一行规则吃遍所有任务

- 成功的最后一步：奖励 0；每一步：奖励 −1（即"用时即扣分"）；失败的 episode 最后一步：一个极大的负常数 c_fail（约 −10 万）。
- 为什么需要 c_fail？一杯 120 秒成功的咖啡回报是 −6000，而一杯 90 秒搞砸的若没有大额惩罚回报是 −500——反而"更高"，价值函数分不清快成功还是快报废。加上 c_fail 后失败轨迹被压到 −100500，类似"快送到时把餐撒了要重罚"。

### 2. 价值函数 = 自己训一个"导航"

- 训练数据零标注成本：**把成功录像倒着数帧**。32 秒叠衣服视频（1600 帧），第 0 帧标签 −1600，第 800 帧标签 −800……网络看到画面就能预测"还剩多久做完"。这是整套系统能规模化的根本原因。
- 输出离散成 201 个桶做分类（交叉熵），用时按桶概率加权还原连续值。
- 网络结构同样是 PaliGemma + SigLIP，输入 3 路画面 + prompt + 元数据。
- **意外收获——失误定位器**：value 曲线平稳下降中突然骤降，对应画面正是"左臂把衣服弄皱了"；机器人自动恢复后曲线回升。价值函数可以兼作运行监控器。

### 3. 优势计算与二值化

- A = （往前看 N=50 步的实际奖励之和 + 第 N 步后的价值）− 当前价值。
- 例：进这一秒前价值说还需 84 秒（−84）；走了 1 秒（奖励 −1），价值说还剩 80 秒（−80）→ A = −1 + (−80) − (−84) = **+3**，比预期多推进 3 秒。
- **二值化**：不直接用数值，设阈值——优势排进前 30%（预训练阶段）/ 40%（微调阶段）记为 positive，其余 negative。只给"跑得最快的路段"盖 positive 章。

### 4. 好坏数据都用，标签区分

π0.5 时代的 AWR 方法把坏样本直接扔掉——但真机数据太贵，扔了白采。π0.6 改为**好坏样本都进训练，只是在输入里标注 advantage positive / negative**。模型既见过正确动作长什么样，也见过错误长什么样，纠错能力由此而来。

### 5. 架构与七阶段训练

- 架构与 π0.5 一致（VLM 出子任务文本 + fast 动作 token，action expert 出 50 步连续动作），唯一变化：**优势标签 token 插在子任务文本之后、动作之前**——只有动作部分的似然带上这个条件，子任务预测不受影响（像骑手先决定下一站去哪，再决定这一段怎么骑）。
- 七阶段流水线：① 海量预训练数据训价值函数 V → ② 全量数据标注 advantage，训出带 advantage 接口的基座 → ③ 人类遥操示范（标签全 positive）监督微调，得到可在真机跑的策略 → ④ 该策略上真机自主跑（成功 / 失败 / 人类接管三种结局，接管段强制 positive）采新数据 → ⑤ 用新数据反向训练新价值函数 V1 → ⑥ 用 V1 重算 advantage（约 40% positive）重复训策略 → ⑦ 迭代循环。
- 结果：每迭代一轮，吞吐量与成功率都提升——RL 迭代本身被证明有效。

## 九、π0.7（2026.4，未开源）：不做微调的通用模型

π0.6 的局限：做咖啡要针对该任务经过好几轮 RL 微调，得到的是"专家型（specialist）"模型。π0.7 的目标：**一个通用模型，开箱即用**，任何场景不微调直接干复杂任务。四大能力：

1. **开箱即用**做灵巧任务：浓缩咖啡、叠衣服、换垃圾袋、削皮等；
2. **指令跟随**：人在旁边说"打开左边抽屉，把胶带放进去"，一条条照做；
3. **跨本体零样本**：从没做过叠衣服训练的双臂 ALOHA 机器人，装上 π0.7 直接零样本叠衬衫，水平相当于专家遥操员第一次上机；
4. **组合泛化**：用没见过的方式组合已有技能（如旁人用语言教它"把红薯放进空气炸锅"），类似大语言模型的"涌现"。

### 1. 前置工作：MEM（多尺度具身记忆）

此前所有 π 模型**没有记忆**——只看当前帧，做不了"擦三块玻璃，记住哪块擦过了"这类任务。MEM 把记忆分两级：

- **短期记忆（稠密）**：最近几秒的画面，处理遮挡、判断物体是否移动过。做法：在视觉编码器（ViT）中每隔 4 层插入一层**时间方向注意力**（因果，只看过去），不引入新参数、可复用预训练权重，历史为零时退化为原 ViT。
- **长期记忆（语义、稀疏）**：如"盐已经加过了""门还没关"——只有几句话但要维持几十分钟。做法：高层策略每步除输出子任务外，还输出并维护一段**语言摘要**，下一步读取并更新摘要。

### 2. 数据：拥抱"次优数据"，标注精细化

- 机器人数据两类：人类遥操示范（实验室/仿真家庭/真实家庭，各平台）+ **大量自主数据**（π0.6 等旧模型跑出来的评价 episode，含大量失败与人类接管数据）——相当于**蒸馏所有 RL 专家模型的行为**，通用模型继承全部 specialist 能力，且自主数据让状态覆盖更广，鲁棒性更强，有时甚至超过专家模型。
- 非机器人数据：人类第一视角（egocentric）视频（新增）+ 网页数据（属性预测、VQA）。
- 每条数据的标注：观测 + **子目标图**（世界模型输出）+ 人工细粒度子任务指令 + **元数据**。

### 3. 元数据标注：让低质量数据变养分

| 项目 | 内容 |
|---|---|
| 速度 | 该 episode 用了多少时间步（快通常意味着失误少） |
| 质量分 | 1~5 分人工打分 |
| 有无失误 | 布尔值 |
| 控制模式 | 关节控制还是末端控制（两种表示混训必须标明，否则模型学成平均） |

消融实验结论：**对低质量数据，如果不加这些元数据标注，性能反而下降；加上标注后它们就成了很好的养分——数据不是关键，标注才是关键。**

### 4. 架构：一个主模型 + 两个"小弟"

- 主干仍是 PaliGemma + action expert（+fast token），与 π0.5/0.6 一致。
- **高层策略模型**（重新拆出，独立模型）：把总任务分解为子任务；还支持 **coaching 模式**——人在旁边一步步用语音下达子任务（如"红薯放空气炸锅"零样本会失败，coaching 一步步教就能完成）。
- **世界模型**：输入当前观测与子任务，**预测执行完后世界应该长什么样**，生成多视角子目标图（前置相机图表达物体/环境的目标状态，腕部相机图表达手/夹爪该夹到哪里）。指令只表达"意图"，子目标图补足"执行细节"。从 14B 图像模型初始化，用 flow matching 训练。
- 输入 prompt 的演进一览：π0（图+任务+本体状态）→ π0.5（+子任务）→ π0.6（+优势标签）→ π0.7（+子目标图 + 速度/质量/失误/控制模式元数据 + 本体状态）——**对数据的标注和输入粒度一步步变细**。

### 5. 训练中的 dropout 策略：防止模型偷懒

随机丢弃上下文的某个成分，目的有二：① 测试时缺某个模态也能工作（灵活性）；② **防退化**——有了"未来的画面"，预测动作会退化成逆动力学（照着结果图反推关节角），模型只抄世界模型。对策：只有 25% 样本带子目标图；带子图时再随机丢 30% 文本；元数据整体丢 15%，其三个分量各丢 5%。

### 6. 推理：三模型异步流水线

高层策略/人出子任务 → 世界模型生成 3 张子目标图 → π0.7 拿观测+子图+子任务+元数据出动作。速度：单张 H100、只开三路相机时一步 38ms；全开（记忆编码器+子目标图）最坏 127ms——世界模型是大头，需 4 卡张量并行 + 量化，**完整系统至少 5 张 H100**。

### 7. 结果与局限

- 指令跟随（14 个没见过的家，厨房场景）：π0.5 约 28% → π0.6 约 54% → **π0.7 约 87%**。
- 一个模型追平此前四个经 RL 专门微调的 specialist 的性能；去掉自主数据会掉点。
- 局限：全新"任务×机器人"组合成功率 60~80%；数据太杂，很难说清是不是真没见过（泛化可能来自已有技能的重叠）。

## 十、全景总结：π 系列演进一览

| 模型 | 时间 | 关键词 | 核心贡献 | 开源 |
|---|---|---|---|---|
| RT-2 | 2023 | 动作当文字输出 | 首创 VLA 范式；慢（1~3Hz） | ✗ |
| OpenVLA | 2024.6 | 开源 | 全流程开源 baseline，70.6% | ✓ |
| **π0** | 2024.10 | 数据+架构+配方 | VLM + action expert（flow matching 一次出 50 步）；预训练+后训练两段式 | ✓ |
| **π0.5** | 2025.4 | 泛化、真实家庭 | 5 类数据混训；高层低层合一（先出子任务再出动作）；第一个可实际部署 | ✓ |
| **π0.6** | 2025.11 | 强化学习 | RECAP 循环：价值函数+优势标注+好坏数据全用；13 小时做咖啡 | ✗ |
| **π0.7** | 2026.4 | 通用、开箱即用 | MEM 记忆；世界模型子目标图；次优数据+精细标注；一个模型追平所有 specialist | ✗ |

**一条主线**：对数据的标注和输入粒度不断变细（指令 → 子任务 → 优势标签 → 子目标图 + 元数据）；训练范式从纯模仿学习 → 模仿+RL → RL 数据反哺通用模型；输出从单帧离散 token → 50 步连续动作块 → 文本+离散+连续三路输出。
