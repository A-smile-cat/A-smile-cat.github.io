会议与期刊是科研成果的两条主要出口。入门02梳理了计算机各方向的顶级会议，这一篇对应地整理**顶级期刊**：它们各自的主题侧重、出版节奏（月刊/双月刊/季刊）、审稿周期的公开统计区间，以及期刊特有的「会议扩展版」投稿惯例。

需要先说明的是：计算机领域的期刊生态与会议并不对称。有些方向（如数据库）会议是绝对主场、期刊是长尾沉淀；有些方向（如体系结构、软件工程）期刊与会议分量相当，顶会论文经扩展后投顶刊是标准流程。选出口之前，先弄清自己方向的天平倾向哪边。

## 一、期刊与会议的四个关键差异

**第一，产出形态不同。** 会议论文挂在会议论文集（Proceedings）里，期刊论文发表在期刊的某一卷（Volume）某一期（Issue）上，有正式的 DOI 与卷期号。国内多数单位的职称与毕业文件里，「期刊论文」与「会议论文」分开统计，CCF 目录也把两者列为并行的两个体系。

**第二，评审周期相差一个量级。** 顶会从投稿到出结果通常是 2–4 个月；顶刊普遍以「年」为单位——软件工程方向的 IEEE TSE、数据库方向的 ACM TODS，公开统计的审稿周期常在 10 个月以上。投期刊前要把这个时间尺度纳入规划，毕业节点紧的尤其如此。

**第三，审稿轮次不同。** 会议是一锤子买卖：接受或拒绝，最多带一次 rebuttal。期刊是「审稿—修改—再审」的循环，大修（major revision）后作者花数月补实验、改论证，再送同一批或新的审稿人，循环两三轮很常见。

**第四，篇幅与完整性要求不同。** 会议论文受页数硬约束（通常 10–14 页），强调单一贡献点的突破性；期刊论文允许更长篇幅，期待更完整的论证、实验与消融分析。这正是「会议版扩写成期刊版」的合理基础。

## 二、会议扩展版：最常见的顶刊投稿路径

计算机领域有一条其它学科少见的惯例：**顶会论文扩展（extension）后投顶刊**。流程通常是——工作先在顶会发表，拿到评审意见；之后把内容扩展 30% 以上（补充实验、消融、理论证明或案例分析），在投稿信中声明与会议版的差异并附上会议信息，投给同方向的顶级期刊。

这条路径的价值在于：会议版快速占领首发权，期刊版沉淀为完整、可引用的长文，两者引用可以互通。但有一条红线——**不允许一稿多投**，也不允许把会议论文原文不改投期刊（会被判自我抄袭，duplicate publication）。扩展必须提供实质性的新增内容。

几个方向的标准去向：体系结构的 ISCA/MICRO/HPCA 论文常扩展投 TC、TOCS、TPDS；软件工程的 ICSE/FSE/ASE 论文常扩展投 TSE、TOSEM；网络的 SIGCOMM/NSDI 论文可扩展投 TON、TOCS。数据库方向则更特殊——SIGMOD/VLDB 的会议版本身就以期刊卷的形式出版（PACMMOD、PVLDB），见下文。

## 三、各方向 A 类期刊速览

以下按 CCF 目录的十个领域整理 A 类期刊。「出版节奏」为刊物官网公布的常规频率，「审稿周期」为公开投稿经验统计的约数，实际以各刊当期说明为准。

### 3.1 计算机网络

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| JSAC | IEEE Journal on Selected Areas in Communications | 通信与网络，每期围绕一个专题征稿 | 月刊 | 3–6 个月 |
| TMC | IEEE Transactions on Mobile Computing | 移动计算、无线网络、普适系统 | 双月刊 | 6–12 个月 |
| TON | IEEE Transactions on Networking | 网络体系结构、协议、性能（原 IEEE/ACM Transactions on Networking） | 双月刊 | 6–12 个月 |

网络方向期刊的显著特点是**专题刊（special issue）传统**：JSAC 每期一个主题、约稿与征稿结合；TON、TMC 也常年围绕热点方向组织专题。专题刊截稿时间独立于常规投稿，关注官网的 CFP 是必要的。

### 3.2 体系结构、并行与存储

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TC | IEEE Transactions on Computers | 计算机系统与体系结构全领域 | 月刊 | 6–12 个月 |
| TPDS | IEEE Transactions on Parallel and Distributed Systems | 并行与分布式计算 | 月刊 | 6–12 个月 |
| TOCS | ACM Transactions on Computer Systems | 计算机系统，偏系统设计与评测 | 季刊 | 6–12 个月 |
| TOS | ACM Transactions on Storage | 存储系统 | 季刊 | 6–12 个月 |
| TACO | ACM Transactions on Architecture and Code Optimization | 体系结构与代码优化交叉 | 季刊 | 6–12 个月 |
| TCAD | IEEE Transactions on Computer-Aided Design of Integrated Circuits and Systems | EDA 与芯片设计自动化 | 月刊 | 6–12 个月 |

这六本都是体系结构方向的 CCF-A 期刊，也是 ISCA/MICRO/HPCA/ASPLOS 论文扩展版的经典去向，其中 TPDS 与并行计算、TPDS/TOCS 与系统类会议的对应关系最紧密。

### 3.3 网络与信息安全

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TDSC | IEEE Transactions on Dependable and Secure Computing | 可信性与安全计算 | 双月刊 | 6–12 个月 |
| TIFS | IEEE Transactions on Information Forensics and Security | 信息取证与安全 | 月刊 | 6–12 个月 |
| TOPS | ACM Transactions on Privacy and Security | 隐私与安全 | 季刊 | 6–12 个月 |

安全四大顶会（S&P、CCS、USENIX Security、NDSS）是本方向的主场，期刊承担扩展版与偏理论、偏形式化的长文。TDSC 与 TIFS 是扩展版最集中的去处。

### 3.4 软件工程、系统软件与程序设计语言

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TSE | IEEE Transactions on Software Engineering | 软件工程全领域 | 双月刊 | 12 个月以上 |
| TOSEM | ACM Transactions on Software Engineering and Methodology | 软件工程方法论 | 双月刊 | 10–15 个月 |
| TOPLAS | ACM Transactions on Programming Languages and Systems | 程序设计语言与系统 | 季刊（不定期） | 6–12 个月 |
| TOCS | ACM Transactions on Computer Systems | （属体系结构领域，系统软件论文亦常投） | 季刊 | 6–12 个月 |

软件工程是「期刊分量最重」的方向之一：TSE 与 TOSEM 并列双子星，公开统计的审稿周期都在一年上下，录用率低、修改轮次多。ICSE/FSE/ASE 的会议论文扩展投这两本刊是本方向的标准成长路径。

### 3.5 数据库、数据挖掘与内容检索

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TODS | ACM Transactions on Database Systems | 数据管理理论与系统 | 季刊 | 12 个月左右 |
| TKDE | IEEE Transactions on Knowledge and Data Engineering | 知识与数据工程，覆盖数据库到挖掘 | 月刊 | 9–14 个月 |
| VLDBJ | Very Large Data Bases Journal | 数据库理论与系统 | 双月刊 | 6–12 个月 |

数据库方向的独特之处：**SIGMOD 与 VLDB 的会议版本身就是期刊卷**——SIGMOD 论文收录在 PACMMOD 卷、VLDB 论文收录在 PVLDB 卷，走的是季度轮/月度轮投稿、期刊式修改的混合模式。独立投 TODS、TKDE、VLDBJ 的，多是扩展版或与会议节奏错开的长文。

### 3.6 人工智能

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| AI | Artificial Intelligence（Elsevier） | 人工智能综合理论 | 月刊（约） | 6–12 个月 |
| TPAMI | IEEE Transactions on Pattern Analysis and Machine Intelligence | 模式识别、计算机视觉、机器学习 | 月刊 | 6–12 个月 |
| IJCV | International Journal of Computer Vision | 计算机视觉 | 月刊（约） | 6–12 个月 |
| JMLR | Journal of Machine Learning Research | 机器学习理论与方法 | 不定期（连续出版） | 3–9 个月 |

AI 方向的期刊与会议分工最极端：新结果几乎都在会议（NeurIPS、CVPR 等）首发，期刊承担扩展版与系统性长文。TPAMI 是整个计算机领域影响因子最高的期刊之一，视觉方向顶会论文（CVPR/ICCV/ECCV）扩展投 TPAMI 是标准路径；IJCV 与之并称视觉双子刊。JMLR 的特殊性在于完全开放获取、评审以会议速度运转，在期刊里独树一帜。

### 3.7 计算机科学理论

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| JACM | Journal of the ACM | 理论计算机科学最高水平 | 双月刊 | 12 个月以上 |
| SIAM J. Comput. | SIAM Journal on Computing | 算法与计算复杂性 | 双月刊 | 12 个月左右 |
| Inf. Comput. | Information and Computation | 理论信息学 | 月刊（约） | 6–12 个月 |

理论方向与众不同：**会议即顶刊**。STOC/FOCS 论文的地位相当于其它方向的顶刊，期刊（JACM、SICOMP）主要承接会议版的详细版本——理论论文的完整证明往往远超会议页数限制，扩展到期刊是常态而非可选项。

### 3.8 图形学与多媒体

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TOG | ACM Transactions on Graphics | 计算机图形学（SIGGRAPH 会刊） | 双月刊 | 6–12 个月 |
| TIP | IEEE Transactions on Image Processing | 图像处理 | 月刊（约） | 6–12 个月 |
| TMM | IEEE Transactions on Multimedia | 多媒体计算 | 月刊（约） | 6–12 个月 |
| TVCG | IEEE Transactions on Visualization and Computer Graphics | 可视化与图形（IEEE VIS 会刊） | 月刊 | 6–12 个月 |

图形学方向的 TOG 和 TVCG 同样是「会议-期刊一体」：TOG 是 SIGGRAPH 及其 Asia 场次的会刊，TVCG 是 IEEE VIS 的会刊——投这两个会，论文直接以期刊卷期形式出版。独立的期刊投稿则承接图像处理（TIP）与多媒体（TMM）长文。

### 3.9 人机交互与普适计算

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| TOCHI | ACM Transactions on Computer-Human Interaction | 人机交互 | 季刊 | 6–12 个月 |
| IMWUT | Proceedings of the ACM on Interactive, Mobile, Wearable and Ubiquitous Technologies | 普适计算（UbiComp 会刊） | 季刊 | 3–6 个月 |

HCI 方向会议主导（CHI 是绝对核心），期刊长文以 TOCHI 为代表。IMWUT 值得单独记住：它是 UbiComp 的会刊，采用**滚动投稿**模式，一年四期，审稿周期在顶刊里偏短，普适计算与移动感知方向的重要发表出口。

### 3.10 交叉与综合

| 期刊 | 全称 | 主题侧重 | 出版节奏 | 审稿周期（约） |
| ---- | ---- | -------- | -------- | -------------- |
| Proc. IEEE | Proceedings of the IEEE | 综合性长文与综述 | 月刊 | 6–12 个月 |
| SCIS | Science China Information Sciences | 中国综合期刊（英文） | 月刊 | 3–6 个月 |
| Bioinformatics | Bioinformatics（牛津） | 计算生物学交叉 | 不定期 | 3–6 个月 |

交叉领域的 A 类期刊覆盖面广、方向分散，Proc. IEEE 以高质量综述著称，适合沉淀系统性总结。

## 四、选期刊还是选会议：一个决策框架

**看方向惯例。** 数据库、AI、理论、图形学：会议是首发主场，期刊用于扩展与沉淀；体系结构、软件工程、网络：会议与期刊并重，扩展版路径成熟；应用交叉方向（如计算生物学）期刊分量更重。

**看时间约束。** 毕业或考核节点以「月」计，会议（2–4 个月出结果）几乎必然是首选；时间充裕、工作完整度高的长文，投期刊能获得更完整的呈现。

**看单位认定。** 部分单位的目录里期刊论文权重高于会议论文；也有些计算机强校把 CCF-A 会议与 A 类期刊完全等同。**动手写之前先查本单位文件**，这比任何领域惯例都有决定性。

**看内容形态。** 单点突破的工作适合会议的页数约束；需要大篇幅理论证明、系统实验与消融分析的工作，天然适合期刊。理论方向的详细证明甚至必须以期刊版承载。

## 五、结语

1. **两条出口，一套目录**：CCF 目录把会议与期刊并行分级，评奖、毕业、职称都可能分别核对，两者都要心里有数。
2. **扩展是惯例，不是可选项的浪费**：顶会论文扩展 30% 以上投顶刊，是计算机领域的标准成长路径，但必须声明差异、避免自我抄袭。
3. **节奏决定选择**：期刊审稿以年计，会议以月计；PACMMOD/PVLDB/TOG/TVCG/IMWUT 这类「会议-期刊一体」的形态介于两者之间，认识清楚它们的混合属性，选出口时就不会错位。
